# JuliaSyntax's lexer and lexical rules, compiled to C

tree-sitter-julia's scanner gets its tokens from **JuliaSyntax's own lexer** (`Tokenize`), compiled from
Julia to C without the Julia runtime:

- identifiers (Unicode, emoji: JuliaSyntax's `is_identifier_char`), numbers, booleans;
- operators, dotted (`.+`, `.=`) and suffixed (`+₁`), in the grammar's precedence classes, which are
  computed from JuliaSyntax's kind predicates (`is_prec_comparison`, `is_prec_plus`, ...) at generation
  time (`kinds.h`);
- keywords; the contextual ones (`abstract`, `mutable`, `primitive`, `public`, `outer`, ...) decided
  as JuliaSyntax's parser does, from the next token (`kernel.jl: contextual_keyword`);
- JuliaSyntax's space-sensitive rule: in a matrix row or in macro arguments, `[x -y]` is `[x (-y)]`,
  while `[x - y]`, `[x-y]`, `[x -= y]`, `[x +₁y]` and `[x .-y]` are one element (`parse_with_chains`):

```julia
ps.space_sensitive && preceding_whitespace(t) && is_both_unary_and_binary(t, isdot) &&
    !preceding_whitespace(peek_token(ps, 2))
```

The grammar keeps the structure: which token kinds are valid where (that is how `x[end]` is an
identifier and `:end` a symbol), precedences, and the tree shape. To follow a JuliaSyntax change,
regenerate.

tree-sitter's lexer cannot go back, so a token's end must be marked while the lexer is there. JuliaSyntax
decides whether a character belongs to a token from at most one more character (outside strings), so the
scanner lexes progressively: one kernel call per character, marks only moving forward
(`scanner.c: lex_jsyntax_token`). It gives the same tokens as JuliaSyntax's lexer on the whole file at every
token of Julia's base + stdlib (1,682,650 tokens).

## Files

| file | what | how |
|---|---|---|
| `src/jsyntax/kernel.c` | JuliaSyntax's `Tokenize` lexer, the space-sensitive and contextual-keyword rules (`kernel.jl`) | generated by `regenerate.sh` |
| `src/jsyntax/kinds.h` | JuliaSyntax kind codes and each kind's grammar class (`gen_kinds.jl`) | generated by `regenerate.sh` |
| `src/jsyntax/unicode_tables.h` | general category, grapheme boundclass, indic conjunct break | generated from Julia's own utf8proc (`gen_unicode.c`) |
| `src/jsyntax/runtime.c` | the little the compiled code needs from libjulia, implemented without it | hand-written |
| `src/jsyntax/jsyntax.c` | one unit, `#include`d by `src/scanner.c` (no binding needs new sources) | hand-written |
| `script/jsyntax/kernel.jl` | the entry point: Julia code calling JuliaSyntax | hand-written |
| `script/jsyntax/tokenize.patch` | JuliaSyntax change: tokenizer lookup tables as isbits tuples | hand-written |

## Pipeline (`regenerate.sh`)

1. JuliaSyntax = Julia 1.13.2's `base/JuliaSyntax` + `tokenize.patch`: `Dict`/`Vector`/`String` lookup
   tables in `tokenize.jl` become isbits tuples (`ConstMap`, binary search), so a lookup compiles to
   code and constant data instead of reading heap objects from Julia's system image. JuliaSyntax's
   own test suite passes with the patch (50/50 test sets).
2. `juliac --trim=safe --output-bc` (JuliaC 0.3.12 library API, `build_bc.jl`; Julia `-O1`) on `kernel.jl`.
3. `kgen.py`: link the bitcode shards, keep only the Julia specialization of the entry and what it
   calls (not the `@ccallable` wrapper, which is what enters the runtime), and remove the remaining
   ties to libjulia and to the system image:
   - exception paths (`noreturn` functions: `throw_boundserror`, …) call `jsk_throw`;
   - safepoint polls (Julia emits them even in allocation-free code) are deleted: there is no GC;
   - `ccall`s (lazily bound through libjulia) call `jsk_*` functions directly;
   - image globals (type objects, error messages, the empty-`Memory` instance) point at distinct dummies;
   - atomic loads/stores become plain ones (all objects are private to one call);
   - stack pointer arrays become `i64` arrays (the code has 64-bit layouts baked in).
4. `llvm-cbe` (LLVM IR → C), then small fixes so the C can live inside `scanner.c`; names and order are
   canonicalized so that the output is byte-for-byte reproducible.
5. `gen_kinds.jl`: kind codes and grammar classes (`kinds.h`).
6. `gen_unicode.c`: tables from the utf8proc inside Julia's `libjulia-internal` (version-checked).

## Where the Julia runtime came in, and what replaced it

| construct (Julia source) | runtime use | here |
|---|---|---|
| `Lexer`, its `IO`, `Vector{StringState}` (mutable, passed to ~40 non-inlined lexer functions, so Julia cannot elide them) | `ijl_gc_small_alloc`, `jl_alloc_genericmemory_unchecked` | bump arena on the C caller's stack, dropped after the call (4 KiB) |
| `push!` on `string_states` | GC write barrier `ijl_gc_queue_root` | no-op (never taken) |
| bounds/inexact/assertion errors, `@assert`, UndefVarError checks | `ijl_throw`, `ijl_bounds_error_int`, `jl_argument_error`, `ijl_undefined_var_error` | `longjmp` to the entry, answer "no" (Wasm: trap). Never taken on Julia's base + stdlib |
| every function with a loop | safepoint poll through the thread state | deleted |
| every function that allocates | GC frame pushed on `pgcstack` (first argument) | a fake, zeroed task |
| `Dict`s / `Vector`s / `String` literals in `tokenize.jl` | system-image objects | `tokenize.patch` |
| `Base.isspace`, `is_id_char`, `isopsuffix`, `isgraphemebreak!` | `ccall`s to utf8proc / `jl_id_char` in libjulia-internal | C copies (MIT) on generated tables |

`nm -u` of the compiled kernel + runtime: `setjmp`/`longjmp`, `memset`, `memmove` (plus the
distribution's stack protector). No Julia, no system image.

## Verification (Julia 1.13.2 base + stdlib + tree-sitter-julia/JuliaSyntax test snippets, 1,875 files)

- The C answers like the same Julia code run natively at every byte position (13,804,851 calls, 0
  differences), compiled with gcc, clang, and wasi-sdk (wasm32, run under wasmtime); never throws.
- About 300 ns per call; the scanner only calls it for whitespace + operator after a matrix/macro element.
- `regenerate.sh` reproduces `kernel.c` and `unicode_tables.h` byte for byte.

## Building llvm-cbe

```
git clone https://github.com/JuliaHubOSS/llvm-cbe && cd llvm-cbe && git checkout 83f1bea
git apply ../llvm-cbe.patch    # link the static libraries of an LLVM release tarball
cmake -G Ninja -B build -DCMAKE_BUILD_TYPE=Release -DLLVM_DIR=$LLVM/lib/cmake/llvm \
  -DCMAKE_C_COMPILER=$LLVM/bin/clang -DCMAKE_CXX_COMPILER=$LLVM/bin/clang++ \
  -DCMAKE_CXX_FLAGS="-stdlib=libc++ -fno-rtti" \
  -DCMAKE_EXE_LINKER_FLAGS="-fuse-ld=lld -stdlib=libc++ -L$LLVM/lib/<triple> -Wl,-rpath,$LLVM/lib/<triple>"
ninja -C build llvm-cbe        # LLVM_CBE=build/tools/llvm-cbe/llvm-cbe
```

## Limits

- Generated from 64-bit Julia: byte offsets assume 8-byte pointer slots. Works on 32-bit targets
  (wasm32 tested) because every pointer slot is 8 bytes; untested on MSVC.
- The scanner passes at most 256 bytes (whole characters) of the line; tree-sitter re-encodes invalid
  UTF-8 as U+FFFD, so on invalid UTF-8 the answer can differ from JuliaSyntax on the raw bytes.
- Strings, characters and comments are still lexed by the hand-written part of `scanner.c` / the
  grammar (see the tree-sitter-julia PR for why).
- Tokens over ~1 KB are split; `for outer::T in xs` reads `outer` as a keyword (JuliaSyntax: an
  identifier, it parses the expression before looking); without C11 threads support (glibc < 2.28) the
  runtime's per-call state is a global, so parsers must not run concurrently.
